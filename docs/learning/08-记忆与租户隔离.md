# 08 记忆与租户隔离

## 本章解决什么问题

区分当前会话、历史摘要和用户画像，并确保不跨租户读取。

## 小白类比

Redis 像工作台上的便签，情景记忆像历史案卷，用户画像像客户档案。租户 ID 是每个柜子的锁。

## 前置知识

了解 Redis Key、TTL 和 ChromaDB Collection。

## 源码阅读顺序

`MemoryContext` → `get_context` → `add_message` → `_compress` → `_search_episodic` → `update_profile`。

## 核心类和函数解释

Redis Key 包含 `tenant_id:user_id:conv_id`。达到 15 条消息时压缩，保留最近 5 条，摘要和画像写入带租户元数据的 ChromaDB。

## 一次真实输入如何流转

请求以租户、用户和会话组成 Redis Key，同时用租户元数据检索历史与画像；回答完成后，脱敏消息再写回同一命名空间。

## 可执行实验

用相同 `user_id/conv_id`、不同 `X-Tenant-ID` 发送请求，验证两边不会看到对方历史。

## 常见错误

只在 API 认证租户，数据库查询却不带租户条件，仍可能泄露数据。

## 自测题及答案

问：为什么画像不保存 Token？答：画像会被反复召回到 Prompt，保存密钥会放大泄露风险。

## 面试表达

“我在 API、Redis Key、向量库元数据和 SQL 查询四层落实租户隔离。”
