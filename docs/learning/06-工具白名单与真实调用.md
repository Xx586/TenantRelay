# 06 工具白名单与真实调用

## 本章解决什么问题

看懂 LLM 如何请求调用工具，以及为什么不能让每个 Agent 调用所有工具。

## 小白类比

员工有门禁卡：技术支持能查错误，只有工单节点能创建工单。

## 前置知识

知道 JSON Schema、函数参数和异步调用。

## 源码阅读顺序

`AgentToolSpec/make_tool` → `build_saas_tools` → Agent `tool_scope` → `BaseAgent._call_llm`。

## 核心类和函数解释

七个工具分别检索文档、查错误、查服务、查租户、查套餐、创建工单和查工单。所有数据工具携带租户，所有调用写入审计表。

## 一次真实输入如何流转

IntegrationAgent 选择 `lookup_api_error`，框架先校验 Schema，处理器带租户上下文查 PostgreSQL，然后写入脱敏审计日志并将结果返给 Agent。

## 可执行实验

查看 `/health` 中每个 Agent 的 `available_tools`，确认 CustomerSuccess 不包含 `create_support_ticket`。

## 常见错误

在 Prompt 中写“不能调用”不等于真正的权限控制；必须不向模型暴露该工具定义。

## 自测题及答案

问：工具参数为什么要用 Schema 验证？答：阻止缺失字段、错误类型和未授权的额外字段进入实际系统。

## 面试表达

“工具权限是代码级白名单，不是只依赖 Prompt 自律。”
