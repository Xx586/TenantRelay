# 01 项目全景与学习路线

## 本章解决什么问题

先建立地图：TenantRelay 不是大模型，而是组织模型、数据和工具的 AI 应用。

## 小白类比

把系统想成企业服务台：前台接请求，分诊员识别问题，调度员选专家，专家查手册和业务系统，最后记录工单与指标。

## 前置知识

会读文件目录、知道 HTTP 请求和 JSON 即可。

## 源码阅读顺序

`api/main.py` → `core/intent_recognizer.py` → `scenarios/saas/orchestrator.py` → `scenarios/saas/agents.py` → `scenarios/saas/tools.py` → `scenarios/saas/store.py`。

## 核心类和函数解释

`chat()` 是入口，`IntentRecognizer` 是分诊员，`SaaSAgentOrchestrator` 是调度员，五个 Agent 是业务专家，`SaaSStore` 是数据访问层。

## 一次真实输入如何流转

```text
/chat → 认证/脱敏 → 记忆 → 意图与实体 → RAG → 主辅 Agent → 工具 → 回写记忆/指标
```

## 可执行实验

先运行 `docker compose config`，找到 `TENANTRELAY_SCENARIO`、PostgreSQL、Redis 和 ChromaDB 四个部分。

## 常见错误

把 Agent 当成独立模型。它们其实共用模型客户端，主要差异是角色契约、工具权限和路由位置。

## 自测题及答案

问：TenantRelay 自己训练大模型吗？答：不训练，它调用外部 LLM，重点是应用编排。

## 面试表达

“我将单轮 LLM 问答扩展成带租户隔离、结构化路由、真实工具和评测闭环的 B2B SaaS 支持系统。”
